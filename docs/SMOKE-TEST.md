# 最小冒烟验证清单

目的：用可重复的手动步骤验证真实聊天与关键工具链路。除特别说明外，使用临时工作区，不要把密钥或敏感文件放进测试目录。

## 前置条件

- Node.js 及项目依赖已安装。
- 配置 `.env` 中的 `HIERO_LLM_ENDPOINT`、`HIERO_LLM_MODEL`、`HIERO_LLM_TOKENS`；令牌仅保存在本机，勿复制到日志或截图。
- 启动后端：在仓库根目录执行 `npm start`。
- 启动前端：在另一终端进入 `frontend`，执行 `npm run dev`，打开 `http://localhost:5173/`。
- 在 UI 中选择新建的临时目录作为工作区。记录所用模型、日期、结果和失败信息（脱敏）。

## A. 真实 LLM 一轮对话

1. 在聊天中发送一个简单且只需文本回答的问题，例如“用一句话说明 2+2 的结果”。
2. 确认收到模型回答，界面没有持续加载或连接错误。
3. 记录：模型 ID、是否成功、耗时；不要记录令牌或完整请求头。

通过标准：收到非空的模型回答，运行期间无网关错误。

## B. `read_file` 分支

1. 在临时工作区创建 `smoke-read.txt`，内容为一段唯一的无敏感文本，例如 `hiero-smoke-read-2026-11`。
2. 在聊天中明确要求读取 `smoke-read.txt` 并复述其中的唯一文本。
3. 确认模型回答内容匹配文件内容；如 Trace 可用，确认出现成功的 `read_file` 记录。

通过标准：回答与文件内容一致，`read_file` 成功；没有对文件进行写入。

## C. Docker `cmd:` 验收路径

1. 确认 Docker CLI 与 Docker daemon 均可用：`docker version` 应同时显示 Client 和 Server 信息。
2. 在临时工作区启动一个仅做只读检查的任务，并设置验收标准 `cmd: node --version`。
3. 确认验收通过，并在 Docker 容器内执行。若项目的 Trace/日志能显示实际命令，确认容器调用带有禁网、只读根文件系统及工作区挂载约束。
4. 负向检查：停止 Docker daemon 后重复一次，确认命令失败关闭，没有回退到宿主机 shell。

通过标准：Docker 可用时容器内命令退出码为 0；Docker 不可用时明确失败且宿主机没有执行该命令。

## 结果记录

每次执行仅记录以下信息：日期、提交 SHA、Node 版本、模型 ID（如适用）、Docker 版本（如适用）、各步骤通过/失败、脱敏错误摘要。不要记录 API key、Authorization header、完整环境变量或真实用户数据。

此清单是手动冒烟验证，不替代自动化测试，也不等于完整安全审计。首次执行尚未完成时，应明确标记为“未验证”，不可把步骤描述当作通过证据。
